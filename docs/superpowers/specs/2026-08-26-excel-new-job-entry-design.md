# Excel 新建任务入口设计

## 背景

Excel 页面只有在没有当前任务时才显示主上传区。一旦存在历史任务，上传入口就被放进旧任务底部默认折叠的“上传另一个工作簿”区域。实际上传接口会创建任务并自动选中，但入口与反馈不够明显，用户容易误以为文件没有上传或新任务没有出现。

2026-08-26 的真实文件 `etsy-listings-a15c4bf0-6e37-437f-a892-b40ac2d07b6d.xlsx` 已成功创建任务 `b67031ec-2a49-49e0-88f4-93e71bc4ab95`，证明问题位于任务入口和状态反馈，而不是文件格式或后端接收。

## 目标

- 无论是否存在旧任务，用户都能立即找到“新建 Listing 任务”。
- 新文件上传成功后立即成为当前任务，主区域显示它的文件名、状态和进度。
- 历史任务继续保留在右侧，当前任务保持明显选中。
- 不增加新路由，不改变 Excel 后端、任务并发或产物规则。

## 界面方案

1. 在页面标题栏右侧放置始终可见的主按钮“新建 Listing 任务”。
2. 没有任务时继续显示现有的大型拖放上传区，方便首次使用。
3. 已有任务时不再显示底部折叠的“上传另一个工作簿”。标题栏按钮直接打开 `.xlsx` 文件选择器。
4. 文件上传期间按钮禁用并显示“正在创建任务…”，防止重复提交。
5. 后端返回新任务后，沿用现有 store 行为：插入历史列表首位、自动选中、开始监听进度，并把焦点移到状态播报区域。
6. 上传失败时保留当前旧任务，显示现有安全错误提示，并允许再次点击标题栏按钮选择文件。

## 组件边界

- `ExcelDropzone.vue` 增加紧凑按钮模式，复用同一套扩展名、大小、拖放和文件选择校验；完整模式保持现有空状态样式。
- `ExcelView.vue` 在标题栏渲染紧凑模式入口，删除旧的折叠上传区，并让失败任务的“重新选择文件”调用同一入口。
- `excel.store.ts` 不改变任务创建和自动选中逻辑。

## 可访问性与响应式

- 新建按钮使用真实 `button` 与明确文本，不依赖图标表达含义。
- 上传中提供禁用状态和文字变化；新任务状态继续通过现有 `aria-live` 播报。
- 移动端按钮保持至少 44px 点击高度；窄屏时标题和按钮允许上下排列。
- 隐藏的文件输入继续由可聚焦按钮触发，并保留 `.xlsx` 限制。

## 验收标准

- 有历史任务、完成任务、失败任务或运行中任务时，页面顶部都能看到“新建 Listing 任务”。
- 页面不再要求展开“上传另一个工作簿”。
- 点击按钮选择文件只创建一个任务；上传期间不能重复创建。
- 创建成功后新任务自动成为当前任务，右侧历史列表第一项被选中。
- 创建失败不清除当前任务，错误提示可聚焦且入口仍可再次使用。
- 空任务页面仍保留完整拖放区。
- 前端单元测试、生产构建和真实页面验证全部通过。
