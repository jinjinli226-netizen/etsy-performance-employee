# Etsy 图片 + Listing 联合训练与 Excel 视觉生成设计规格

日期：2026-08-17
状态：方案已口头确认，等待书面规格复核
目标运行环境：Windows、本机 FastAPI 服务、`etsy-performance-us` Hermes Profile

## 1. 背景

现有训练脚本只采集 Etsy Listing 的标题、描述和少量结构化文本，发送学习消息时没有附加图片。因此，当前知识候选反映的是文字规律，不能证明员工学会了从服装主图识别造型、轮廓、结构、装饰和可见配件，更不能证明它会在 Excel 生产任务中把图片与同一行文字结合起来。

本方案把训练改造成可审计的多模态学习流水线：从指定工作簿读取 Etsy 店铺链接，为每个店铺选择一个尚未训练的 Listing，采集主图和 Listing 文本，先提取视觉事实，再生成知识候选，由独立 AI 审批器和确定性安全门共同决定是否自动激活。Excel 生产任务使用同一套事实优先级；没有行图片的商品不再退化为纯文本生成，而是明确跳过。

这里的“训练”是基于多模态证据持续提炼、审批和激活可检索规则，不是修改或微调基础模型权重。

## 2. 目标与非目标

### 2.1 目标

- 一条命令读取现有工作簿中的 Etsy 店铺 URL，并完成“店铺 → Listing → 主图 + 文本 → 视觉事实 → 五类知识候选 → AI 审批 → 自动激活”的闭环。
- 每个训练样本只使用 Etsy Listing 的第一张主图。
- 图片只贡献肉眼可见事实；Listing 文本与图片冲突时，Listing 文本优先。
- 独立审批调用必须在候选激活前执行；审批不通过的候选不得激活。
- 对通过 AI 审批的低风险五类知识，在确定性安全门也通过后自动激活，不要求用户逐条点击。
- 保存 Listing ID、来源 URL、图片哈希、文本快照哈希、视觉事实、冲突、候选、审批决定和激活版本，支持去重、追踪和回滚。
- Excel 生产时把第一张行图片与同一行文字共同作为商品事实来源；无图片行跳过且保持源单元格不变。
- 始终另存 Excel 结果，不修改用户原文件。

### 2.2 非目标

- 不抓取或使用 Listing 的第二张及后续图片。
- 不从图片猜测材质、精确尺寸、套装承诺、未展示配件、性能、品牌、认证、价格、库存或物流承诺。
- 不自动发布 Etsy Listing，不改价、不操作店铺账号。
- 不把竞品原文或原图直接作为日常生成检索内容。
- 不绕过 Etsy 验证、验证码、访问限制或浏览器安全机制。
- 不保证任意陌生品类都能一次生成完美结果；本期验收范围是 Etsy 表演服及相邻服饰/配件类目。

## 3. 已确认决策

| 事项 | 决策 |
|---|---|
| 训练输入 | Etsy 主图 + 同一 Listing 文本 |
| 生产输入 | Excel 商品行第一张图片 + 同一行文字 |
| 图片数量 | 每个样本/商品行只使用第一张图 |
| 冲突优先级 | Listing 或 Excel 行文字优先于图片推断 |
| 无图生产行 | 跳过，不做纯文本生成 |
| 知识类别 | `title_structure`、`tag_taxonomy`、`occasion_vocabulary`、`buyer_instruction_style`、`category_mapping` |
| 审批方式 | 独立 AI 审批 + 确定性安全门 |
| 激活方式 | 两道门均通过后自动激活；否则保留 proposed 或标记 rejected |
| 店铺来源 | 用户现有 Excel 工作簿中的 Etsy shop URL |
| 初始工作簿 | `C:\Users\25941\Downloads\Etsy表演服工作任务清单表-飞书云文档.xlsx`，运行时通过参数传入，不写死在产品代码中 |
| 原文件保护 | 训练工作簿只读；生产工作簿始终另存副本 |

## 4. 方案比较

### 4.1 方案 A：单次模型调用直接从图片和文本生成知识

优点是调用少、实现快。缺点是图片观察、文字冲突处理、知识抽象混在一次自由生成里，失败时无法判断是“看错图”还是“抽象错规则”，审批也缺少稳定的中间证据。

### 4.2 方案 B：先结构化视觉事实，再生成或审批知识（采用）

第一阶段只做可见事实提取并记录字段级来源；第二阶段只基于已合并事实生成抽象候选；第三阶段用独立上下文审批。该方案调用更多，但可测试、可追踪、可复用到 Excel 生产，并能严格执行“文字优先”和禁止视觉臆测。

### 4.3 方案 C：传统图像分类器或本地视觉模型

优点是调用成本可控。缺点是需要独立标注集、训练和部署，且难以覆盖快速变化的表演服细节。当前没有足够标注数据，不适合作为第一版主路径。

## 5. 总体架构

```text
训练工作簿（只读）
  → 提取 Etsy shop URL
  → 浏览店铺并选择未训练 Listing
  → 采集 Listing 文本 + 第一张主图
  → 图片安全校验、归一化、SHA-256 去重
  → 视觉事实提取器（独立模型调用）
  → 文字优先事实合并器（确定性代码）
  → 五类知识候选生成器（独立模型调用）
  → 独立 AI 审批器（新会话、无生成器上下文）
  → 确定性安全门与并发版本检查
  → 自动激活或保留候选
  → 训练运行、样本、审批与激活审计

Excel 商品行
  → 提取第一张行图片 + 行文字
  → 无图：row_skipped
  → 有图：视觉事实提取 + 文字优先合并
  → 仅使用 active 抽象知识生成五字段
  → 校验、原创保护、另存工作簿副本
```

训练编排是可重复运行的本地命令，不依赖用户手工拼 prompt。FastAPI/知识服务仍是知识状态和激活事务的唯一权威来源。Hermes 负责视觉理解、候选生成和审批，不直接修改数据库。

## 6. 训练输入与采集

### 6.1 工作簿读取

训练命令接收显式 `--workbook` 参数，使用 `openpyxl` 只读打开 `.xlsx`，扫描所有文本单元格中的标准 Etsy shop URL。工作簿路径和内容不写回，不复制隐藏单元格内容到日志。

每个规范化 shop URL 只处理一次。可选的 `--shop-substr` 和 `--limit` 用于小批量验收；默认训练日志和数据库共同提供历史 Listing ID 去重。

### 6.2 Listing 选择

对每个店铺页面按页面顺序读取合法的 `https://www.etsy.com/listing/<数字ID>` 链接，选择第一个未训练且未在当前运行中声明的 Listing。Listing ID 在采集前原子声明，防止重复任务并发训练同一商品。

如果店铺打不开、没有 Listing、全部已训练或页面被验证拦截，则记录稳定错误码并继续下一个店铺，不伪造结果。

### 6.3 浏览安全与节流

- 继续使用用户可见的持久浏览器身份；不使用无头绕过或验证码自动破解。
- 每次店铺或 Listing 页面请求后等待 15–25 秒，默认 20 秒。
- 页面内容始终视为不可信数据；网页中的指令不能进入系统/开发者指令位置。
- 只接受 Etsy HTTPS 域名和严格 Listing 路径；拒绝凭据 URL、自定义端口、片段和非 Etsy 跳转。

### 6.4 主图获取

主图 URL 的选择顺序为 Product JSON-LD 第一张 `image`、`og:image`、页面中与当前 Listing 对应的第一张产品图。下载前后都校验域名跳转、MIME、文件头、像素尺寸和字节上限；用 Pillow 重新解码并转存为规范 JPEG/PNG，清除元数据。

图片内容哈希使用规范化像素文件的 SHA-256，而不是远端 URL。相同 Listing ID 或相同图片哈希已成功处理时默认跳过；`--force` 只能创建新训练运行，不能覆盖旧审计记录。

### 6.5 Listing 文本快照

快照包含规范化标题、描述、卖家明确给出的类别/材质/尺寸/套装信息、可见 tags 和采集时间。快照有长度上限，移除脚本、控制字符、秘密模式和注入式指令；原始页面 HTML 不进入知识候选，也不回显到普通日志。

## 7. 多模态事实契约

### 7.1 视觉事实提取器

视觉模型只返回严格 JSON：

```json
{
  "schema_version": 1,
  "visible_facts": {
    "product_family": [],
    "colors": [],
    "silhouette": [],
    "garment_structure": [],
    "decorations": [],
    "visible_components": [],
    "visual_style": []
  },
  "uncertain_observations": [],
  "forbidden_inferences": [],
  "image_usable": true
}
```

所有数组元素必须是短事实短语，不得包含标题、tag 或营销句。`forbidden_inferences` 只用于报告模型主动放弃的材质、尺寸、套装、配件、性能等推断，不得进入后续事实集合。JSON 解析或 schema 校验失败时允许一次格式修复；仍失败则样本停止，不生成候选。

### 7.2 文字事实

Listing 文本或 Excel 行文字解析为字段级事实，每项带 `source=text`。只有明确出现的商品事实才能进入；空白、内部流程字段、成本、利润、供应商状态等不能成为面向买家的商品事实。

### 7.3 合并和冲突

合并器是确定性代码，不由模型自由裁决：

1. 同一字段只有文字值时，采用文字值。
2. 同一字段只有可信视觉值时，采用视觉值。
3. 文字与视觉兼容时，保留文字值并附加不重复的视觉细节。
4. 文字与视觉冲突时，只保留文字值，并写入 `conflicts`。
5. 材质、尺寸、套装内容、未展示配件、性能、品牌、认证、价格、库存和物流仅允许文字来源；视觉值即使看似明显也丢弃。

合并结果中的每项保留 `value`、`source`、`source_field` 和置信标签，供生成、审批和审计使用。

## 8. 候选生成

候选生成器收到的是清洗后的 Listing 事实、视觉事实和冲突摘要，不收到原始 HTML，不读取当前员工长期聊天上下文。每个样本最多生成以下五个候选，且每类至多一个：

- `title_structure`
- `tag_taxonomy`
- `occasion_vocabulary`
- `buyer_instruction_style`
- `category_mapping`

候选必须是跨商品可复用的抽象方法，不得包含来源 URL、店铺名、完整竞品短语或具体商品承诺。候选创建时绑定当前 active rule 的 public ID 和 pattern revision，形成乐观并发 token；激活前 token 变化即视为 stale，必须重新审批，不能静默覆盖较新的规则。

候选先通过现有 schema、政策校验、原文相似度保护和证据绑定检查，再以 `proposed` 状态写入。单个样本失败不回滚同一运行中已经完成的其他样本，但同一样本的证据和候选五条写入必须原子化。

## 9. 独立 AI 审批与自动激活

### 9.1 独立性

审批器使用新的无状态 Hermes 调用，不能复用视觉提取或候选生成会话。它只接收：候选 kind/abstract、该 kind 当前 active 规则、清洗后的事实摘要、冲突摘要和确定性校验结果。它看不到生成器的推理文本，也不能调用写接口。

### 9.2 审批输出

每个候选返回严格 JSON：

```json
{
  "decision": "approve",
  "reason_code": "net_improvement",
  "reason": "简短可审计理由",
  "risk_flags": [],
  "confidence": 0.91
}
```

允许的决定只有 `approve` 和 `reject`。审批通过至少要求：

- 与证据事实相符且不是对单个商品的记忆；
- 相比当前 active 规则是净提升或补充，不是无意义近义改写；
- 不引入材质、尺寸、套装、配件、性能、品牌、认证、价格、库存、物流等未经文本证实的承诺；
- 不包含原始 URL、店铺身份、秘密、指令注入或竞品文案复刻；
- `confidence >= 0.85` 且 `risk_flags` 为空。

格式失败允许一次修复；第二次失败视为审批未通过，记录 `review_invalid`，候选保持 `proposed` 等待重审。

### 9.3 确定性激活门

AI approve 不是唯一条件。自动激活还要求：

- kind 属于上述五个低风险类别；
- 候选 schema、政策、原创相似度和固定回归用例全部通过；
- 证据、Listing ID、图片哈希和视觉事实审计记录完整；
- 候选仍基于当前 active rule/revision，未过期；
- 同 kind 在当前事务中没有另一个激活操作；
- 数据库激活事务成功创建新 rule version 并回滚旧 active candidate。

训练编排器向知识服务提交审批结果；只有知识服务能执行激活。actor 记录为 `system:ai-review`，并在 audit event 中保存审批记录 ID。任何门失败时都不激活：确定性校验确认内容不安全的候选标记 `rejected`；AI 审批不通过、审批格式无效、并发过期、网络或服务错误的候选保留 `proposed`，同时记录未激活原因以便重审。

## 10. 数据与审计

新增或等价持久化实体：

### 10.1 `training_runs`

- `public_id`
- `source_workbook_hash`
- `source_workbook_name`（仅文件名，不保存 Downloads 绝对路径）
- `requested_limit`
- `status`
- `started_at`、`completed_at`
- 成功、跳过、失败、审批通过、激活计数

### 10.2 `training_samples`

- `run_id`
- `shop_url`
- `listing_id`、`canonical_url`
- `source_timestamp`
- `listing_snapshot_hash`
- `main_image_hash`、受控本地证据路径
- `visual_facts`、`merged_facts`、`conflicts`
- `status`、稳定 `error_code`

Listing ID 与图片哈希分别建立索引。数据库不保存原始浏览器 Cookie、用户 Profile 路径或凭据。

### 10.3 `training_reviews`

- `sample_id`、`candidate_id`、`kind`
- 审批器版本、prompt/schema 版本
- `decision`、`reason_code`、清洗后的 `reason`
- `risk_flags`、`confidence`
- 审批时 active rule token
- 激活后的 rule version 或未激活原因
- `reviewed_at`

原始下载图片位于 DataDirectory 的受控 evidence 子目录，仅作为审计证据，不加入生产检索；知识迁移必须至少包含图片哈希、视觉事实、审批和规则血缘。是否携带原图由迁移包显式选项决定，默认不携带以控制体积。

## 11. Excel 生产路径

### 11.1 行图片提取

现有 `inspect_workbook.py` 已能按锚点把行图片提取到任务目录，并把 `image_paths` 写入 manifest。本期保留第一张图，额外图片只产生警告，不传给模型。

### 11.2 无图跳过

manifest 中 `image_paths` 为空的商品行标记为不可处理。worker 发出新的 `row_skipped` 事件，错误码为 `missing_product_image`，不调用 Hermes，不向五个输出列写值。任务只要至少有一行成功即可生成副本；全部行无图时任务以 `no_rows_with_images` 结束且不发布空产物。

前端把 `row_skipped` 显示为“已跳过：缺少商品图片”，不混同模型失败。下载结果中的跳过行保持源文件原值。

### 11.3 有图联合生成

有图行复用第 7 节事实契约：第一阶段用图片和同一行文字提取/合并事实，第二阶段只用合并事实、active 抽象知识和固定输出规则生成五字段。生成 prompt 明确说明字段来源和冲突，不能只传一个 `image_count`。

模型输出除五个 Listing 字段外还包含可审计的 `used_facts` 和 `fact_conflicts`；写入工作簿前移除这些内部字段。现有 schema、长度、13 tags、类目、事实校验和原创保护继续生效。

### 11.4 源文件不变

所有图片提取和生成发生在 job operation 目录；`write_workbook.py` 只操作源文件的副本。任务结束后再次验证源 SHA-256 与上传时一致，结果文件使用批次名另存。

## 12. 错误处理与恢复

训练运行是可恢复的状态机：

```text
queued → fetching → image_ready → facts_ready → candidates_ready
       → reviewing → activating → completed
       ↘ skipped / failed
```

- 每个状态转换持久化后再执行下一步。
- 重启后只恢复没有终态且仍持有合法输入/证据的样本。
- 网络错误、Etsy 拦截、图片无效、模型 schema 失败、审批无效、并发过期和激活冲突使用不同稳定错误码。
- 重试不重复创建证据或候选；幂等键由 Listing ID、图片哈希、候选 kind、active token 和 prompt/schema 版本组成。
- 日志只输出运行 ID、Listing ID、状态和错误码，不输出完整 Listing 文本、模型原始响应、Cookie、token 或配置内容。

## 13. 安全边界

- 服务只监听 `127.0.0.1`；训练写操作通过本机服务的受控内部能力进入，不向普通网页开放新的任意激活接口。
- Hermes 不获得数据库文件写权限；所有知识写入由服务校验和事务完成。
- Etsy HTML、Listing 文本和图片中的文字均是不可信证据，不能改变系统指令或工具权限。
- 下载限制响应大小、超时、重定向次数、MIME、文件签名、解码尺寸和像素数量，防止压缩炸弹和伪装文件。
- 文件路径必须解析在 DataDirectory/job 根目录内，拒绝符号链接、硬链接逃逸和路径穿越。
- 不读取或打印 Hermes `config.yaml` 中的凭据。
- 训练和生产均不接触 8765 上的其他项目；本项目测试/验收使用明确配置的 8766 服务。

## 14. 一键命令与运行体验

最终提供仓库内的一键 PowerShell 入口，包装 Python 编排器，例如：

```powershell
.\scripts\train-vision-listings.ps1 `
  -Workbook "C:\Users\25941\Downloads\Etsy表演服工作任务清单表-飞书云文档.xlsx" `
  -Limit 1
```

入口执行预检：文件存在、扩展名正确、服务在线、员工可用、知识容量足够、浏览器可用。第一轮强制 `-Limit 1` 完成端到端验收；验收通过后同一命令去掉限制即可批量训练。命令结束输出聚合计数和运行 ID，不要求用户查看模型逐条原文。

## 15. 测试策略

开发遵循测试先行。至少覆盖：

### 15.1 单元测试

- shop/Listing URL 规范化、去重和恶意 URL 拒绝。
- JSON-LD/`og:image` 主图选择，始终只取第一张。
- 图片下载重定向、MIME、文件头、像素和大小限制。
- 视觉事实 schema 与禁止推断字段。
- 文字优先合并、兼容追加、冲突记录和受限字段丢弃。
- 审批 JSON schema、阈值、risk flags、stale token 和确定性门。
- Listing ID、图片哈希和幂等重试。
- Excel 无图 `row_skipped`，有多图只用第一张。

### 15.2 集成测试

- 使用本地伪 Etsy HTML 和图片完成“店铺 → Listing → 候选 → AI approve → 激活”闭环，不访问公网。
- 模拟审批 reject、审批格式失败、激活冲突和重启恢复。
- 使用含图/无图/多图三行的测试工作簿，验证只处理有图行、只发送第一张图、跳过行不写入、源哈希不变。
- 验证日常生成只读取 active 知识，不读取原始竞品图片或文本。
- 验证审计能从激活 rule version 追溯到 candidate、review、visual facts、图片哈希和 Listing ID。

### 15.3 真实验收

1. 对现有工作簿副本运行 `Limit 1`。
2. 确认真实 Etsy Listing 的主图哈希、文字快照、视觉事实和五类审批记录完整。
3. 只允许审批和确定性门都通过的候选激活，且 active rule version 增加。
4. 用包含一行真实图片和文字的 Excel 副本跑生产任务，确认模型调用收到第一张图，并生成五字段。
5. 用无图行确认跳过且输出列不变。
6. 对生成结果做人工业务抽检后，才解除批量训练限制。

真实验收失败时不得声称系统已具备稳定的图片 + Listing 能力，也不得直接批量激活。

## 16. 验收标准

本功能完成必须同时满足：

- 训练审计中每个成功样本都有非空主图哈希、视觉事实和 Listing 文本哈希。
- 同一图片确实作为模型图片输入，而不是只把 URL 或 `image_count` 写进文字 prompt。
- 五类候选都有独立审批记录；未审批或 reject 的候选为零自动激活。
- 所有自动激活都有 `system:ai-review` 审计和可回滚 rule version。
- 图片/文字冲突测试证明文字值胜出，禁止视觉推断不会进入生成事实。
- Excel 无图行显示为 skipped，不触发模型且不改变五个输出字段。
- Excel 有图行只发送第一张图，生成结果来自图片、行文字和 active 知识的联合输入。
- 原训练工作簿与原生产工作簿哈希始终不变。
- 新增测试通过；现有前端 75 项测试和生产构建不回退。后端既有 Windows ACL 基线缺陷单独记录，新增功能相关测试必须独立全绿。

## 17. 发布顺序

1. 完成纯函数、数据契约和测试夹具。
2. 完成采集与安全图片下载，不接真实知识激活。
3. 完成视觉事实、事实合并、候选和审批的 fake-model 集成测试。
4. 完成知识服务自动激活事务和审计。
5. 完成 Excel `row_skipped` 与多模态生产路径。
6. 在隔离 DataDirectory 上做一条真实 Listing 和一个 Excel 副本验收。
7. 复核改动、员工资产哈希和 provisioning manifest。
8. 合并代码并在停机、备份后同步正式 Profile 技能；重新校验员工。
9. 正式环境只跑 `Limit 1`，人工抽检通过后再一键批量。

在第 9 步完成前，不能向用户承诺“随便丢一个商品都能做得很好”；准确说法只能是已通过规定品类、规定输入契约和验收样本的能力验证。
