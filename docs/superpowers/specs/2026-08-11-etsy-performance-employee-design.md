# Etsy 表演服 Listing 数字员工设计规格

日期：2026-08-11  
状态：已完成方案评审，等待用户审阅书面规格  
目标运行环境：Windows、Hermes Agent CLI v0.18.2、本地浏览器

## 1. 背景与目标

当前需要为 Etsy 表演服店铺建立一个独立数字员工。员工在本机培养成熟后，可以迁移到其他 Windows 电脑继续工作。系统需要同时解决两类日常任务：

1. 上传 Excel 后，按商品行生成固定的五个 Listing 字段，并下载不覆盖原文件的新副本。
2. 通过一个长期对话框持续训练、纠错、添加 Etsy 竞品链接和管理员工知识。

竞品只用于离线学习和提炼行业规律。日常生成必须根据商品自身信息和员工已经形成的抽象知识原创完成，不引用、拼接或改写具体竞品文案。

## 2. 范围

### 2.1 本期范围

- 创建全新的 Hermes 表演服员工 Profile。
- Vue 3 本地网页工作台。
- 长期对话、附件、图片、Excel 和 Etsy 链接输入。
- Excel 动态表头识别、逐行生成、质检和新副本导出。
- Etsy 竞品链接采集、清洗、评分和知识提炼。
- 可迁移知识库、规则版本、审批、回滚和审计。
- 低风险知识的半自动升级。
- 本机到另一台电脑的员工迁移和验收。

### 2.2 非本期范围

- 珠宝数字员工。
- 自动登录 Etsy 店铺或自动发布 Listing。
- 改价、广告、退款、订单和财务操作。
- 重新训练或微调基础大模型权重。
- 在日常生成时实时搜索 Etsy 或引用具体竞品。
- 多用户云端部署。

## 3. 已确认决策

| 事项 | 决策 |
|---|---|
| 运行方式 | 本地网页后台 |
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | FastAPI 模块化单体 |
| 员工 | 新建独立 Hermes Profile，不克隆或复用现有员工 |
| 主界面 | Excel 自动化、长期对话两个核心入口 |
| Excel 输出 | 保留原文件，生成带批次号的新副本 |
| 输出字段 | 固定五个表头，位置和列号不固定 |
| 输入字段 | 自动理解同一商品行的动态表头和内容 |
| 生成规则 | 可调整、可版本化；表内说明文字只作为参考 |
| 竞品来源 | 用户在长期对话中随时发送 Etsy Listing 链接 |
| 竞品用途 | 清洗并提炼抽象知识，不在生成阶段引用具体竞品 |
| 学习方式 | 低风险知识半自动升级，高风险规则人工审批 |
| 迁移方式 | 可移植知识、规则、技能和对话；凭据与登录状态不迁移 |

## 4. 固定输出契约

系统只向以下五个固定表头写入生成结果：

1. `head titles`
2. `13 tags`
3. `SPECIFICATION`
4. `Category`
5. `Instructions for buyers`

定位规则：去除表头前后空格、统一换行和 Unicode 空白后进行精确名称匹配，不依赖列号、列顺序或 Excel 字母列。

如果任一固定表头缺失、重复或位于合并单元格歧义区域，任务停止写入并展示可操作错误，不猜测目标位置。

## 5. 动态输入理解

固定输出字段以外的同一行内容都是候选输入。字段识别分三步：

1. 根据表头名称、单元格类型和样例值识别图片、日期、SKU、产品备注、备注、尺码表、供应商、中文标题等语义角色。
2. 计算字段与 Listing 生成的相关度，自动忽略成本、物流、利润、内部状态等无关字段。
3. 对当前工作簿结构生成模板指纹，保存已确认的字段映射；结构变化时重新识别。

低置信度字段不会直接变成商品事实。员工在预览区标记缺失或冲突信息，避免编造材质、尺寸、套装内容和配件。

## 6. 用户体验

### 6.1 信息架构

前端只有两个一级工作入口：

- `Excel 自动化`
- `长期对话`

历史任务、历史会话、设置、知识审批和迁移入口放在侧边栏或次级抽屉中，不与主工作流竞争注意力。

### 6.2 Excel 自动化页面

流程：

```text
上传 Excel
→ 识别 Sheet、五个输出字段和商品行
→ 展示识别摘要
→ 一键生成
→ 逐行显示状态
→ 预览生成结果与警告
→ 下载新 Excel
```

逐行状态包括：`等待`、`生成中`、`质检中`、`待确认`、`成功`、`失败`、`已取消`。

成功行可以查看五字段结果；待确认行显示缺失事实；失败行显示可重试原因。原文件始终只读保存，导出文件名包含原文件名、批次号和生成时间。

### 6.3 长期对话页面

交互采用类似 ChatGPT 的熟悉模式，但不复制其品牌或专有视觉：

- 左侧历史会话列表。
- 中间连续消息流。
- 底部固定输入框和附件按钮。
- 流式回复。
- 支持文字、图片、Excel、普通文件和 Etsy 链接。
- 工具状态用紧凑状态行展示，不输出冗长内部日志。
- 学习结果显示 `已学习`、`待审批`、`已隔离`、`已撤销`。

用户可以使用自然语言完成：

- 学习一个 Etsy 链接。
- 纠正标题、Tag、分类和写作风格。
- 查看员工学到了什么。
- 撤销或恢复某条规则。
- 用最新知识重新处理 Excel。

### 6.4 检查抽屉

右侧检查抽屉默认收起，只显示：

- 当前规则版本。
- 生成置信度。
- 五字段质检结果。
- 缺失或冲突的商品事实。
- 学习候选、审批和回滚记录。

不展示“本次引用了哪些竞品”，因为生成阶段不引用具体竞品。

### 6.5 视觉系统

采用适合长期运营的连续深色工作台：

- 近黑中性画布和分层表面。
- 单一暖色强调主操作、选中态和进度，占屏幕面积保持克制。
- 中性无衬线字体，兼容中文。
- 4–8px 精确圆角、低对比细边框和克制阴影。
- 不使用紫蓝渐变、玻璃拟态、发光球、粒子和多层卡片嵌套。
- 动画只用于状态变化，持续 120–240ms，并支持减少动态效果。
- 桌面使用稳定侧栏；移动端侧栏和检查区变成抽屉。

必须完整实现空白、加载、错误、离线、禁用、部分成功、键盘焦点和移动端状态。

## 7. 总体架构

```text
Vue 3 本地工作台
        │
        ▼
FastAPI 本地服务
├── Chat Service
├── Excel Job Service
├── Hermes Adapter
├── Competitor Learning Service
├── Knowledge Service
├── Validation Service
├── Learning & Approval Service
└── Migration Service
        │
        ├── SQLite 主数据
        ├── 文件与附件目录
        ├── JSONL 可迁移备份
        └── 可重建语义索引
```

采用模块化单体而非微服务。所有模块在一个本地进程边界内运行，但通过明确接口交互，降低初期运维成本并保留后续拆分能力。

## 8. 技术栈

### 8.1 前端

- Vue 3
- TypeScript
- Vite
- Vue Router
- Pinia
- VueUse
- Lucide 图标
- SSE 或 WebSocket 流式消息和任务进度
- Vitest + Vue Test Utils
- Playwright 端到端测试

界面使用项目自有设计 Token 和小型基础组件层，不引入难以定制的大型 UI 框架。

### 8.2 后端

- Python 3.11+
- FastAPI
- Pydantic 结构化契约
- SQLAlchemy 2
- Alembic 数据库迁移
- SQLite + FTS5
- pytest

后台任务第一版使用带数据库状态的本地任务执行器，默认并发为 2。任务状态持久化，应用重启后将未完成任务标记为可恢复或可重试。任务接口预留队列适配层，未来可切换到 Redis/RQ 或其他队列。

### 8.3 Excel 适配层

Excel 处理通过 `WorkbookAdapter` 接口隔离：

- 读取工作表、表头、单元格、嵌入图片和样式信息。
- 从原文件创建副本。
- 只写五个目标单元格。
- 保留现有格式、公式、图片和表格结构。

第一版实现 Windows 本地 Excel/OpenXML 适配器，并使用用户提供的真实工作簿建立保真回归测试。其他电脑只要满足 Windows 与项目运行依赖即可迁移；如环境没有桌面 Excel，则由 OpenXML 路径完成基础读写并在兼容性检查中提示限制。

## 10. 会话隔离

系统有两类上下文：

### 10.1 长期教学会话

- 保存完整用户对话和附件。
- 用于纠错、添加竞品、形成知识候选和查询员工能力。
- 原始聊天内容不自动进入生产知识。

### 10.2 Excel 行任务会话

- 每个商品行创建独立任务 ID 和独立临时上下文。
- 只读取当前行、当前规则版本和正式生效知识。
- 不读取其他商品的临时上下文。
- 不读取未审批或未生效的聊天内容。

该隔离是防止不同 SKU 串数据的核心机制。

## 11. 知识库设计

### 11.1 四层结构

```text
evidence/      原始 Etsy 链接、快照、附件和来源
knowledge/     清洗后且允许生成使用的抽象知识
experience/    生成、修改、接受、拒绝和失败经历
policies/      硬规则、可学习策略、版本和回滚
```

原始竞品文案只存在于 `evidence`，没有生成检索权限。生成阶段只能检索 `knowledge` 中已经提炼和批准的抽象模式。

### 11.2 主要数据实体

- `conversations`
- `messages`
- `attachments`
- `excel_jobs`
- `excel_rows`
- `generation_versions`
- `competitor_sources`
- `competitor_snapshots`
- `knowledge_patterns`
- `knowledge_evidence_links`
- `rule_versions`
- `feedback_events`
- `learning_candidates`
- `approval_events`
- `audit_events`

### 11.3 知识类型

- 表演服商品类型和风格词汇。
- 英文搜索意图和关键词体系。
- 商品特征到 Etsy Category 的映射。
- 标题组织方法。
- Tag 组合方法。
- `SPECIFICATION` 写作结构。
- `Instructions for buyers` 的信息组织方式。
- Excel 表头和字段语义映射。
- 用户偏好、常见纠错和失败模式。

## 12. 竞品学习流程

用户在长期对话中发送 Etsy Listing 链接后：

```text
验证 Etsy 链接
→ 获取公开页面信息
→ 将网页视为不可信数据并隔离页面指令
→ 保存原始证据和时间
→ 去重、完整性检查和语义清洗
→ 相关性、完整度、时效性、可信度评分
→ 从多个样本提炼抽象规律
→ 高置信度低风险规律自动进入测试区
→ 中等置信度规律进入待审批
→ 低质量样本隔离
```

原始竞品数据不得直接成为生成上下文。抽象规律必须跨多个独立样本或得到用户反馈验证，避免从单条 Listing 过度概括。

## 13. 原创生成流程

```text
读取当前商品行
→ 动态识别有效字段和图片
→ 清洗当前商品信息
→ 构建商品事实清单
→ 检索正式抽象知识
→ 生成结构化五字段 JSON
→ 确定性格式质检
→ AI 事实一致性复核
→ 与竞品语料做相似度检测
→ 过度相似则重新生成
→ 预览或自动通过
→ 写入新 Excel 副本
```

相似度检测只能用于防复制质检，不能将命中的竞品文本反馈给生成器用于改写。

## 14. 生成输出结构

Hermes 返回结构化对象：

```json
{
  "head_titles": "string",
  "tags": ["13 tag values or current rule count"],
  "specification": "string",
  "category": "string",
  "instructions_for_buyers": "string",
  "confidence": 0.0,
  "fact_warnings": [],
  "quality_warnings": [],
  "rule_version": "string"
}
```

后端负责将结构化字段映射到 Excel 表头。模型没有直接编辑整个工作簿的权限。

## 15. 可调整规则

Excel 中类似第 2 行的提示说明属于参考规则。导入时系统可以识别并展示候选规则，但正式生成使用后台的版本化规则集。

可调整项包括：

- 输出语言。
- 标题词数或字符数。
- Tag 数量和单个 Tag 长度。
- `SPECIFICATION` 点数、标题和 emoji 要求。
- Category 输出格式。
- 买家说明的结构和必填信息。

每次生成记录规则版本，规则变化不追溯覆盖历史结果。

## 16. 半自动学习

### 16.1 可自动升级的低风险知识

- 关键词排序和组合。
- 标题结构。
- Tag 搭配。
- 描述结构和表达偏好。
- 表头语义映射。
- 竞品样本质量识别规律。

### 16.2 永远需要人工批准的高风险知识

- 商品事实规则。
- 材质、尺寸、套装和配件推断。
- 安全、合规和版权规则。
- 固定五字段契约。
- 覆盖、删除和批量修改行为。
- 账号、凭据和外部发布权限。

### 16.3 默认升级门槛

低风险候选只有同时满足以下条件才可从测试区自动生效：

- 至少 3 个相互独立的有效证据或 3 次一致的已接受人工修改。
- 置信度不低于 0.85。
- 与当前硬规则无冲突。
- 在回归测试集中没有引入质量下降。
- 保存变更依据、前后版本和回滚点。

候选状态：`proposed`、`testing`、`active`、`rejected`、`rolled_back`。

## 17. 数据存储与迁移

### 17.1 本机数据

- SQLite 保存结构化主数据。
- 员工独立目录保存附件、证据、模板和导出文件。
- JSONL 保存可读、可审计的迁移备份。
- 语义索引属于派生数据，可在新电脑重建。

### 17.2 迁移包包含

- 员工 `SOUL.md`。
- 员工专属技能。
- 正式知识和证据索引。
- 规则与版本历史。
- Excel 字段映射。
- 对话、审批、纠错和失败经验。
- 数据库迁移版本。
- 文件清单、校验和和导入说明。

### 17.3 迁移包不包含

- API Key。
- Cookie、验证码和浏览器登录状态。
- Gateway Token。
- 本机绝对路径。
- 其他 Hermes 员工的文件、记忆和会话。

新电脑导入后，重新配置模型凭据和浏览器身份，校验迁移包，运行数据库迁移，重建语义索引，并执行员工和 Excel 最小验收测试。

## 18. 安全边界

- 服务默认只监听 `127.0.0.1`。
- 所有上传先复制到员工受控工作目录。
- Etsy 页面是外部不可信输入，网页内容不能改变系统指令、工具权限或审批规则。
- 日志、数据库、知识库和迁移包不保存秘密值。
- 模型只能返回五字段结构化结果和分析信息，工作簿写入由后端控制。
- 不绕过验证码、地区限制、平台风控和访问限制。
- Etsy 请求设置节流、退避和缓存，遇到阻断停止并提示，不进行规避。
- 重要知识删除、规则回滚和批量重生成保留审计记录。

## 19. 错误处理

| 错误 | 处理 |
|---|---|
| 缺少或重复固定输出表头 | 阻止写入，展示具体表头问题 |
| 商品行资料不足 | 标记待确认，不编造事实 |
| SKU 重复 | 独立标记冲突行，要求确认处理方式 |
| Hermes 不可用 | 保留任务并允许恢复或重试 |
| 模型超时或限流 | 指数退避，有上限重试，保留原任务 |
| Etsy 链接失效或受限 | 标记证据失败，不进入知识库 |
| 竞品内容异常或疑似注入 | 隔离样本，禁止知识晋升 |
| 五字段格式不合格 | 自动修复一次，仍失败则待确认 |
| 与商品事实冲突 | 阻止自动通过 |
| 与竞品文本过度相似 | 丢弃结果并重新原创生成 |
| Excel 被占用 | 不覆盖，提示关闭文件后重试 |
| 导出中断 | 删除未完成临时副本，保留任务记录 |

## 20. 非功能要求

### 可维护性

- 前后端均按业务模块组织。
- Hermes、Excel、存储和任务队列通过适配器隔离。
- 所有数据库变更使用 Alembic。
- 所有生成和学习行为有结构化契约和版本。

### 可靠性

- 原 Excel 永不原地覆盖。
- 任务状态持久化。
- 单行失败不影响其他行导出。
- 知识和规则可以回滚。
- 迁移包有校验和。

### 性能

- 第一版支持单批至少 100 个商品行。
- 默认同时处理 2 行，避免模型限流和上下文串扰。
- 聊天和任务进度以流式方式更新。
- 历史任务和会话分页加载。

### 可扩展性

- 可添加新的输出字段契约，而不修改员工核心会话层。
- 可新增其他 Etsy 员工，但每个员工保持独立 Profile 和知识命名空间。
- 可将 SQLite 替换为 PostgreSQL。
- 可将本地任务执行器替换为外部队列。
- 可将 FastAPI 保持为本地服务或部署为受控内网服务。

## 22. 验收标准

1. `etsy-performance-us` 是空白新建 Profile，未克隆或复制任何其他员工状态。
2. 创建前后 default 关键文件哈希一致。
3. 新员工最小真实模型调用和 Doctor 核心检查通过。
4. 用户可在本地网页进行长期对话并上传四类输入。
5. 用户可上传示例 Excel，系统动态定位五个输出表头。
6. 一个商品填一行，多个商品分别填多行，结果不串行。
7. 原 Excel 不变，生成新副本并保留样式与图片。
8. 竞品链接经过清洗和抽象后形成知识；原文没有生成检索权限。
9. 日常生成不访问或引用具体竞品，输出通过原创相似度检查。
10. 低风险知识按门槛半自动升级，高风险知识必须审批。
11. 员工知识、规则、技能和对话可迁移到另一台电脑。
12. 移动端和桌面端关键工作流均可完成。

## 24. 架构决策记录

### ADR-001：模块化单体优先于微服务

- 决策：Vue 3 前端配合 FastAPI 模块化单体。
- 原因：当前是单机、单员工业务，微服务会增加部署和故障面。
- 代价：单进程资源共享，需要通过模块接口和后台任务隔离长任务。
- 演进：任务、知识和存储均有适配层，规模扩大后可以单独拆分。

### ADR-002：全新 Hermes Profile

- 决策：使用 `etsy-performance-us` 空白 Profile。
- 原因：避免人设、记忆、会话、凭据和业务秘密串线。
- 代价：模型和技能需要重新显式配置并单独验收。
- 替代方案：克隆现有员工被拒绝，因为不符合隔离目标。

### ADR-003：正式知识与原始竞品证据分离

- 决策：生成阶段只能检索抽象知识，不能检索原始竞品文本。
- 原因：保证原创，降低复制、提示注入和单样本偏差风险。
- 代价：增加知识提炼和证据关联流程。
- 替代方案：生成时检索相似竞品被拒绝。

### ADR-004：Excel 行任务与长期聊天隔离

- 决策：长期聊天负责教学，每个 Excel 商品行使用独立任务上下文。
- 原因：防止不同 SKU 串数据，并阻止未确认闲聊影响生产结果。
- 代价：需要显式知识晋升和任务上下文构造。

### ADR-005：SQLite 为主数据，JSONL 为迁移格式

- 决策：本地主数据使用 SQLite，可移植备份使用 JSONL。
- 原因：单机部署简单，同时避免数据库版本成为迁移唯一入口。
- 代价：需要维护导入导出和 schema 版本。
- 演进：存储接口允许以后迁移 PostgreSQL。

### ADR-006：原文件只读，新副本输出

- 决策：不原地修改用户上传文件。
- 原因：降低数据丢失风险，支持审计和回滚。
- 代价：会产生批次文件，需要历史文件清理策略。
