# Excel 瞬时超时恢复设计

## 背景与证据

批次 `ae510c30-d5cd-4c26-aea6-c1e2261e321e` 共识别 38 个有图商品行。36 行完成，第 3 行和第 17 行在模型调用阶段失败，最终任务停在 37%。两张失败图片均可读取，大小与成功行相近；将这两行改为串行后，图片识别和 Listing 生成均在 120 秒内完成。因此根因是并发模型调用的瞬时失败，不是 Excel 或图片损坏。

## 目标

保留正常批次的三路并发速度，同时让少量瞬时模型失败在并发批次结束后获得额外的串行恢复机会。真正不可恢复的商品行仍使整批失败，禁止发布不完整工作簿。

## 方案

- 每行允许总计五次尝试。
- 首次尝试继续参加有界并发批次。
- 首次失败后，当错误属于超时、进程失败、数字员工暂时不可用或模型暂时把可读图片判为不可用时，在并发批次完全结束后串行补跑，最多再尝试四次。
- 并发阶段已耗尽内部修复的视觉 JSON、Listing JSON、schema 和原创性模型输出错误，也允许在批次排空后串行重做整行；工作簿结构、事实安全和真实缺图仍不进入该恢复范围。
- 成功行与失败行的事件契约、工作簿写入契约及不发布半成品策略保持不变。

## 错误处理

若串行补跑成功，正常生成完整工作簿。若五次尝试仍失败，记录最后一次安全错误并使任务失败；不得把模型原始错误或提示词写入用户可见事件。

## 测试

回归测试覆盖第五次才成功的进程级瞬时错误、首次误判 `image_unusable` 后成功，以及五次图片确实不可用时仍拒绝发布。测试必须先在旧实现上失败，再由最小实现修复；随后运行 Excel 技能测试和后端全套测试。

## 最终产物校验补充

真实工作簿在模型阶段全部完成后暴露出第二个独立问题：生成器只选择可见工作表，但最终产物校验统计了隐藏历史模板中的重复输出表头。最终校验必须采用与生成器一致的可见表范围；隐藏表保持原样并且不参与“固定表头恰好一份”的计数。可见表内的重复表头仍然必须拒绝。

## 并发模型输出恢复补充

后续真实批次出现多个 `row_failed` 事件在并发批次结束后同一时间落库，说明这些行的错误不在进程级瞬时错误白名单内。并发场景中，已经耗尽阶段内 schema 修复的格式、视觉结构、Listing 结构或原创性错误，也应在并发批次完全排空后获得串行整行重做机会。真实缺图、工作簿结构错误和事实安全错误仍然不进入该恢复范围。生产并发从三路降低到两路，以降低模型通道压力。

## 大工作簿连接与图片误判补充（2026-08-26）

真实批次 `2d257a0a-817a-447b-87af-d09a8bb89c5b` 的 50,132,885 字节工作簿在 26% 因单行 `image_unusable` 失败；同一行隔离重跑 46 秒后成功，证明该错误可能是瞬时视觉模型误判。同时，前端 SSE 使用 190 秒绝对计时器，即使服务持续发送进度也会主动断开，所以页面会显示“连接数字员工超时”。

Excel 作业事件流不再设置绝对总时限，只接受用户取消或真实网络中断；后端 worker 的默认硬上限为 4800 秒（80 分钟）。`image_unusable` 纳入五次有界重试，但真实不可用图片在预算耗尽后仍使整批失败。修复后，同一源文件以批次 `a15c4bf0-6e37-437f-a892-b40ac2d07b6d` 完成到 100%，生成 47,430,540 字节产物并通过 SHA-256、固定五字段、26 行规则及 172 张内嵌图片保真校验。
