# Etsy 网站与数字员工部署迁移指南

> 适用范围：把本机运行的 Etsy 表演服网站、数字员工、训练知识和业务数据迁移到另一台 Windows 10/11 电脑。
>
> 最后验证：2026-08-19，代码基线 `983a394`。本地网站、数字员工和真实 22 行图片工作簿已跑通；结果 22/22 行完整，描述为 5 段 emoji 卖点。

## 1. 先确认迁移边界

当前系统是本机单用户应用，不是公网网站。默认只监听：

- 网站：`http://127.0.0.1:5173`
- 后端 API：`http://127.0.0.1:8765`
- 当前这台电脑因为 8765 被其他项目占用，实际使用后端端口 `8766`

本指南覆盖 Windows 电脑之间的本地迁移。若要部署成任何人都能从公网访问的网站，必须另外增加账号登录、权限隔离、HTTPS、反向代理、服务器数据库、对象存储、任务队列和秘密管理，不能直接把当前端口暴露到互联网。

## 2. 系统由哪几部分组成

| 部分 | 默认位置 | 是否需要迁移 |
| --- | --- | --- |
| 网站和后端代码 | 项目仓库目录 | 必须 |
| 业务数据库 | `DataDirectory\app.db` | 必须迁移，或通过员工迁移包导入 |
| 对话附件 | `DataDirectory\attachments` | 仅完整目录迁移包含 |
| Excel 作业和产物 | `DataDirectory\excel-jobs` | 仅完整目录迁移包含 |
| 训练图片证据 | `DataDirectory\training-evidence` | 仅完整目录迁移包含 |
| 已审批知识和原创保护数据 | 数据库与 `DataDirectory\trust` | 完整目录迁移或员工迁移包均可 |
| Hermes 员工 Profile | `%LOCALAPPDATA%\hermes\profiles\etsy-performance-us` | 新电脑重新创建，不直接复制凭据 |
| Hermes/Codex 登录 | 本机凭据存储 | 不迁移，必须在新电脑重新登录 |
| 临时运行数据 | `DataDirectory\runtime` | 不迁移 |

这里有两种迁移方式：

1. **标准迁移（推荐）**：代码 Git Bundle + 员工迁移 ZIP。适合干净地换电脑，保留对话、知识、规则、审批和审计记录，不带登录凭据。
2. **完整克隆**：代码 Git Bundle + 停机后的完整 DataDirectory 备份。额外保留附件、训练图片、历史 Excel 源文件和产物，占用空间更大。

两种业务数据方式二选一。不要先恢复完整 DataDirectory，再向同一目录导入员工迁移 ZIP，否则会产生数据冲突。

## 3. 源电脑：准备迁移材料

所有命令都在 PowerShell 中执行。先按实际路径修改变量：

```powershell
$ProjectRoot = 'D:\元序AI\etsy-performance-employee'
$DataDirectory = Join-Path $env:LOCALAPPDATA 'etsy-performance-employee\data'
$BackupRoot = 'D:\EtsyEmployeeMigration-2026-08-19'
$BackendPort = 8766
$ApiBase = "http://127.0.0.1:$BackendPort"
New-Item -ItemType Directory -Path $BackupRoot -Force | Out-Null
```

### 3.1 记录代码版本并确认工作区

```powershell
Set-Location $ProjectRoot
git status --short
git rev-parse HEAD
```

如果 `git status --short` 有未提交修改，先确认这些修改是否需要迁移。不要只复制某几个源文件，否则仓库、员工 Profile 和校验清单可能失去一致性。

### 3.2 导出员工迁移包（标准迁移）

导出时网站必须正在运行，并且 `DataDirectory` 必须与启动时一致：

```powershell
Set-Location $ProjectRoot
.\scripts\package-employee.ps1 `
  -ApiBase $ApiBase `
  -DataDirectory $DataDirectory `
  -OutputPath (Join-Path $BackupRoot 'etsy-performance-us.zip')
```

该 ZIP 包含可移植的对话、抽象知识、规则版本、审批/回滚、审计记录和员工资产；不包含 OAuth、API Key、浏览器身份、附件二进制、训练原图或历史 Excel 产物。脚本会验证文件大小、SHA-256 和 ZIP 文件头。

### 3.3 停止网站

当前电脑使用 8766 时：

```powershell
Set-Location $ProjectRoot
.\scripts\start.ps1 -BackendPort 8766 -Stop -DataDirectory $DataDirectory
```

如果网站是在前台启动窗口中运行，也可以在那个窗口按 `Ctrl+C`。不要按进程名批量结束全部 Python 或 Node 进程。

### 3.4 可选：制作完整业务数据备份

只有在服务已经停止后才能复制 `app.db`。下面命令跳过临时 `runtime` 目录：

```powershell
$FullDataBackup = Join-Path $BackupRoot 'data-full'
New-Item -ItemType Directory -Path $FullDataBackup -Force | Out-Null
robocopy $DataDirectory $FullDataBackup /E /XD (Join-Path $DataDirectory 'runtime') /COPY:DAT /DCOPY:DAT /R:2 /W:1
if ($LASTEXITCODE -gt 7) { throw "DataDirectory backup failed: robocopy exit $LASTEXITCODE" }
```

不要复制 `runtime\migration-capability` 或 `.start-pids.json`。它们只属于原电脑的当前运行实例。

### 3.5 打包网站代码

本仓库当前没有远程 Git 地址，推荐创建可校验的 Git Bundle：

```powershell
Set-Location $ProjectRoot
git bundle create (Join-Path $BackupRoot 'etsy-performance-employee.bundle') --all
git bundle verify (Join-Path $BackupRoot 'etsy-performance-employee.bundle')
```

最终迁移介质至少应包含：

- `etsy-performance-employee.bundle`
- `etsy-performance-us.zip`，或 `data-full` 目录
- 需要继续处理的 Excel 模板和源文件副本

把这些材料保存到仅本人可访问的磁盘；迁移包虽然不含登录凭据，仍包含业务记录。

## 4. 新电脑：安装运行环境

安装并确认以下版本或兼容的新版本：

- Python 3.11
- Node.js 24
- pnpm 11
- uv
- Git for Windows
- Hermes CLI 0.18.2
- Codex CLI

检查：

```powershell
py -3.11 --version

uv --version
git --version
hermes --version
codex --version
```

从 Git Bundle 恢复项目：

```powershell
$Bundle = 'E:\Migration\etsy-performance-employee.bundle'
$ProjectRoot = 'D:\元序AI\etsy-performance-employee'
git clone $Bundle $ProjectRoot

```

## 5. 新电脑：重建并登录数字员工

### 5.1 创建新的 Hermes Profile

先确认 `%LOCALAPPDATA%\hermes\profiles\etsy-performance-us` 不存在。创建脚本会拒绝覆盖同名 Profile；如果新电脑已有同名目录，先停止相关程序并把整个旧目录改名备份，不要覆盖其中的文件。

```powershell
Set-Location $ProjectRoot
.\scripts\provision-employee.ps1 `
  -Provider openai-codex `
  -ModelId gpt-5.4 `
  -ReasoningEffort high
```

### 5.2 重新登录 Hermes 和 Codex

网站对话/训练使用 Hermes Profile；Excel 图片识别与 Listing 生成使用 Codex CLI，因此两边都要在可见终端完成登录：

```powershell
hermes -p etsy-performance-us auth add openai-codex --type oauth
hermes -p etsy-performance-us auth status openai-codex

codex login
codex login status
```

不要复制原电脑的 `.env`、OAuth 文件、API Key、Cookie 或浏览器 Profile，也不要把登录返回值粘贴到聊天、日志或迁移文档中。

### 5.3 校验员工资产

```powershell
Set-Location $ProjectRoot
.\scripts\verify-employee.ps1 -RunModelCheck -RunDoctor
```

只有该命令通过，才继续启动网站。如果仓库员工技能文件、Profile 副本和 `provisioning-manifest.json` 哈希不一致，不要手工跳过校验。

## 6. 新电脑：恢复业务数据

准备一个专用、非 OneDrive、非网络盘、非目录联接的数据目录：

```powershell
$DataDirectory = 'D:\EtsyEmployeeData'
$BackendPort = 8765
$ApiBase = "http://127.0.0.1:$BackendPort"
```

如果 8765 已被占用，改用 8766；启动、导入和停止命令必须始终使用同一个端口。

### 6.1 方式 A：导入员工迁移 ZIP（推荐）

先以空的 `DataDirectory` 启动网站。启动前设置当前已验证的 Excel 生成引擎：

```powershell
$env:ETSY_EMPLOYEE_MODEL_ENGINE = 'codex'
$env:ETSY_EMPLOYEE_CODEX_MODEL = 'gpt-5.4'
$env:ETSY_EMPLOYEE_ROW_WORKERS = '3'
$env:ETSY_EMPLOYEE_HERMES_MAX_TURNS = '30'
$env:ETSY_EMPLOYEE_EXCEL_WORKER_TIMEOUT_SECONDS = '4800'

Set-Location $ProjectRoot
.\scripts\start.ps1 -DataDirectory $DataDirectory -BackendPort $BackendPort
```

这个窗口会持续运行。另开一个 PowerShell 窗口执行导入。下面通过 curl 配置的标准输入传递本机能力令牌，避免把令牌放进子进程命令行：

```powershell
$Package = 'E:\Migration\etsy-performance-us.zip'
$CapabilityPath = Join-Path $DataDirectory 'runtime\migration-capability'
$Capability = (Get-Content -LiteralPath $CapabilityPath -Raw -Encoding ascii).Trim()
$CurlConfig = "header = `"X-Migration-Capability: $Capability`""

# 第一次只检查，不写入
$CurlConfig | curl.exe --config - --silent --show-error --fail-with-body `
  --form "file=@$Package;type=application/zip" `
  "$ApiBase/api/migration/imports?dry_run=true"

# 只有返回 ready=true、conflicts=[] 后才执行正式导入
$CurlConfig | curl.exe --config - --silent --show-error --fail-with-body `
  --form "file=@$Package;type=application/zip" `
  "$ApiBase/api/migration/imports?dry_run=false"

Remove-Variable Capability,CurlConfig
```

正式导入返回 `imported=true` 且 `ready=true` 才算成功。`credential_status=pending` 是正常的，因为模型凭据不会随迁移包迁移。

### 6.2 方式 B：恢复完整 DataDirectory

不要先启动目标网站。把停机备份恢复到一个原本不存在或为空的专用目录：

```powershell
$FullDataBackup = 'E:\Migration\data-full'
$DataDirectory = 'D:\EtsyEmployeeData'
New-Item -ItemType Directory -Path $DataDirectory -Force | Out-Null
robocopy $FullDataBackup $DataDirectory /E /COPY:DAT /DCOPY:DAT /R:2 /W:1
if ($LASTEXITCODE -gt 7) { throw "DataDirectory restore failed: robocopy exit $LASTEXITCODE" }
```

确认目标中没有旧的 `runtime\migration-capability` 和 `.start-pids.json` 后，再按 6.1 的环境变量启动网站。完整目录恢复后不要再导入员工 ZIP。

## 7. 迁移后验收

### 7.1 服务检查

```powershell
Invoke-RestMethod "$ApiBase/api/health"
Invoke-RestMethod "$ApiBase/api/employee/status"
Invoke-WebRequest 'http://127.0.0.1:5173/excel' -UseBasicParsing | Select-Object StatusCode
```

预期：后端 `status=ok`，员工状态可用，页面 HTTP 状态为 200。

### 7.2 数据检查

在网页中确认：

- 历史对话存在；
- 已激活知识规则和候选数量与源电脑一致；
- 审批、回滚和训练记录可见；
- 完整目录迁移时，附件与历史 Excel 任务也存在；
- 标准迁移包方式下，附件和历史 Excel 二进制缺失属于预期，不代表导入失败。

### 7.3 真实 Excel 冒烟测试

只上传源文件的副本。建议先用 1–3 行小表，再验证完整表：

- 每个有图商品行五个输出字段都不为空；
- 标题为 3–14 个单词；
- 标签恰好 13 个、去重、每个不超过 20 个字符；
- 描述恰好 5 行，每行以 emoji 开头；
- 不凭空声称尺寸、材质、手工制作或套装内容；
- 原图片、超链接、公式、Sheet 名和布局保留；
- 任一有图商品行最终失败时，系统不发布残缺工作簿。

验收成功后再停掉源电脑上的旧实例，保留源电脑备份至少一个完整业务周期。

## 8. 日常启动与停止

每次新开 PowerShell 窗口后，Excel 引擎环境变量都要重新设置，或者写入一个仅包含非秘密配置的本地启动包装脚本：

```powershell
$env:ETSY_EMPLOYEE_MODEL_ENGINE = 'codex'
$env:ETSY_EMPLOYEE_CODEX_MODEL = 'gpt-5.4'
$env:ETSY_EMPLOYEE_ROW_WORKERS = '3'
$env:ETSY_EMPLOYEE_HERMES_MAX_TURNS = '30'
$env:ETSY_EMPLOYEE_EXCEL_WORKER_TIMEOUT_SECONDS = '4800'
.\scripts\start.ps1 -DataDirectory 'D:\EtsyEmployeeData' -BackendPort 8765
```

停止：

```powershell
.\scripts\start.ps1 -DataDirectory 'D:\EtsyEmployeeData' -BackendPort 8765 -Stop
```

大表超过默认的 80 分钟时，可把 `ETSY_EMPLOYEE_EXCEL_WORKER_TIMEOUT_SECONDS` 提高到 `14400`；不要通过关闭校验、提高并发到 4 以上或允许残缺文件来换速度。

## 9. 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面提示“无法连接本地服务” | 后端未启动、端口不一致或已被占用 | 检查 `Get-NetTCPConnection -State Listen`，用同一 `BackendPort` 重启 |
| Profile verification failed | 仓库、Profile 和 manifest 哈希不一致 | 不跳过；重新 provision 或从可信版本同步后再验证 |
| Hermes/Codex logged out | 凭据未迁移是正常现象 | 在新电脑分别重新登录 |
| 导入返回 409 | 目标 DataDirectory 已有冲突数据 | 不删除现有库；换一个空目录重新 dry-run |
| 导入返回 422 | ZIP 内容或版本校验失败 | 不强行解压修改；重新从源电脑导出 |
| Excel 作业 `rows_failed` | 至少一个有图商品行重试后仍失败 | 保留源文件，检查网络/模型登录后整单重跑 |
| Excel 作业超时 | 表太大或模型响应慢 | 把总时限提高到 14400，或把表拆成小批次 |
| `knowledge_capacity_exceeded` | 原创保护证据容量已满 | 停止新增训练，恢复容量正常备份或由维护人员整理 |

## 10. 回滚方案

迁移期间不要覆盖源电脑数据。目标电脑验收失败时：

1. 停止目标网站；
2. 保留失败的目标 DataDirectory 供排查，不要直接删除；
3. 改用另一个全新的 DataDirectory 重新 dry-run/import，或恢复停机完整备份；
4. 源电脑继续使用原项目、原 Profile 和原 DataDirectory；
5. 修复后重新执行 Profile 校验和 Excel 冒烟测试。

迁移完成的最低判定标准是：代码版本正确、员工资产校验通过、Hermes/Codex 均已登录、导入无冲突、网站/API 正常、真实 Excel 副本完整生成。
