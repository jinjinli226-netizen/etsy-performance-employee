## 5. 训练流水线（给竞品喂知识）

### 5.1 事件格式（最容易踩的坑，务必遵守）

后端 `parse_final_envelopes` 只接受两种控制事件：
1. `learning_batch` — payload 含 `evidence_items[]`（url/title/snapshot/tags/source_timestamp）**和 `candidates[]`**
2. 独立 `knowledge_candidate` 事件**带 `evidence_urls` 会被判 `envelope_invalid` 拒绝**（解析器对候选 payload 是 `extra=forbid` 且无 evidence_urls 字段）

**唯一可行格式 = 单个 `learning_batch` 事件，候选放在 payload.candidates 数组里，用 `evidence_urls` 绑定**：

```json
{"event":"learning_batch","payload":{"evidence_items":[{"url":"https://www.etsy.com/listing/4423319969","title":"...","snapshot":"...","tags":[],"source_timestamp":"2026-08-15T00:00:00Z"}],
"candidates":[
  {"kind":"title_structure","summary":"...40-200字抽象规则...","confidence":0.5,"evidence_urls":["https://www.etsy.com/listing/4423319969"]},
  {"kind":"tag_taxonomy","summary":"...","confidence":0.5,"evidence_urls":["https://www.etsy.com/listing/4423319969"]}
]}}
```

其他硬性要求：
- `source_timestamp` **必填** → 提示词里直接给当前 UTC 时间，否则模型会反复调终端 `date` 空转
- 证据 URL 必须在消息内容里（`allowed_urls` 信任边界，员工不能自行引入新 URL）
- evidence_items ≤5、candidates ≤5；summary 12-2000 字符、不得含 URL/具体事实断言
- 提示词必须**模板化**（给出完整 JSON 骨架让模型填），xhigh→high 后模型才能稳定落笔；并明令「不要调用任何工具/不要推理」

### 5.2 抓取（真实浏览器，绕 DataDome）

- 普通爬虫、无头/有头 Playwright 都被 DataDome 拦截（403 / CAPTCHA / `dd_referrer`）
- **DrissionPage + 真实 Chrome + 共享持久化 Profile + 预热访问 etsy.com + 重试** 可以稳定通过
- 抓取脚本路径：`fetch_listing.py`；系统 Python（已装 DrissionPage）：`C:\Users\25941\AppData\Local\Programs\Python\Python311\python.exe`
- ⚠️ **频率红线**：~40 分钟内近百次真实浏览器访问会触发 IP 级限流（`ERR_CONNECTION_TIMED_OUT`，连普通 HTTP 都超时）。冷却后自动恢复。批量时保持 **每单间隔 15-25 秒**、共享 Profile

## 7. 已排查并解决的技术坑（新接手者必读）

| 症状 | 根因 | 解法 |
|---|---|---|
| 学习操作 completed 但 0 候选 | 独立 `knowledge_candidate` 带 `evidence_urls` 被解析器拒 | 候选放 `learning_batch.payload.candidates`（见 5.1） |
| 员工只输出推理面板无正文 | xhigh 推理 + 轮次不足 | `reasoning_effort: xhigh→high`（Profile config.yaml，清单 reasoningEffort 已同步）；后端 `ETSY_EMPLOYEE_HERMES_MAX_TURNS=30` |
| 反复调终端 `date` | 提示词要时间戳 | 提示词直接给当前 UTC 时间 |
| Excel 行级失败 | run_task `MAX_TURNS=6`、单行 120s 超时 | 已改 30 / 480s（仓库+Profile+清单哈希三方同步） |
| `invalid_worker_event` | worker stdout 是 GBK，中文/¥/emoji 导致 UTF-8 解码崩 | 技能脚本顶部强制 `sys.stdout.reconfigure(encoding="utf-8")` |
| 作业生成成功却 `cleanup_failed` | WPS 看图进程锁住操作目录 | storage.py 清理加重试；**发现 WPS 窗口显示 excel-jobs 目录文件时关闭它** |
| 重启后端 verify 失败 | hermes 每次用技能后再生 `.usage.json` | verify-employee.ps1 允许清单已加这两项 |
| Etsy 全部超时 | 高频访问触发 IP 限流 | 降频、共享 Profile、预热、冷却后恢复 |
| 大表一次跑不完 | 作业总时限过短 | 当前默认 `ETSY_EMPLOYEE_EXCEL_WORKER_TIMEOUT_SECONDS=4800`（80 分钟）；确认模型仍在正常响应后再按需提高 |
| 任一行失败整单作废 | 技能原契约 | 已改弹性模式（部分成功也出工作簿，失败行保持原值并事件标注） |

**Profile 一致性铁律**：任何 `employee/skills/etsy-performance-listing/` 下的文件改动，必须同步 3 处且哈希一致，否则启动验证失败：
1. 仓库：`D:\元序AI\etsy-performance-employee\employee\skills\etsy-performance-listing\...`
2. Profile：`%LOCALAPPDATA%\hermes\profiles\etsy-performance-us\skills\etsy-performance-listing\...`
3. 清单：`%LOCALAPPDATA%\hermes\profiles\etsy-performance-us\provisioning-manifest.json` 的 `assetHashes` 对应项
   （改完用 `scripts\verify-employee.ps1` 自检）
